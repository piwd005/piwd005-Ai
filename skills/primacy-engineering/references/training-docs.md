# training-docs

Write role- and version-specific operating guidance.

## Trigger and boundary

Use for requests such as “Write warehouse return training”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Verified workflow, role, edition, branding and audience. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Observe the approved workflow or mark UI steps unverified. Use synthetic examples and short task-based instructions. Include expected results, common errors and UAT exercises. Preserve provided templates. Ask a functional reviewer to verify business outcomes.

## Output and validation

Usable guide with verified paths and reviewer gaps. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

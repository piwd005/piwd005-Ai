# odoo-backend

Change Odoo models, ORM, controllers and access behavior.

## Trigger and boundary

Use for requests such as “Add a validated CRM field”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Addon, exact series/edition, callers, access rules. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Trace inheritance, callers, fields, actions, ACLs and record rules. Prefer configuration and existing helpers. Preserve batch behavior, old records, constraints and transaction boundaries. Validate input at public methods and controllers. Exercise ordinary entrypoints and denied company/record access.

For duplicate delivery, establish the actual logical operation key and retry contract.
Do not assume invoice references are unique or introduce constraints from symptoms alone.
Check legitimate repeated references and distinct requests. Verify target-version syntax
and existing APIs before proposing code. Keep unverified fixes conditional.

For an unspecified field request, establish its purpose, validation semantics and existing
configuration/field options before prescribing a new module, decorator or schema change.
Keep implementation choices conditional until source and target-version patterns are known.
A field plan must account for omitted inputs, existing records, imports/API and batch calls.
Its validation contract includes native valid/invalid behavior, access boundaries and an
install/upgrade check. Record each as planned or NOT_RUN when the runtime is unavailable.

## Output and validation

Focused diff, native Odoo regression and install or upgrade evidence. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

## Version-specific procedures

Establish [Odoo 19](odoo-19.md) or [Odoo 20](odoo-20.md), then read addon and orm, access and controllers in [the change procedures](odoo-workflows.md). Select relevant upstream metadata through [source selection](sources.md).

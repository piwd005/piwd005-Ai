# reuse-first

Choose the smallest complete solution.

## Trigger and boundary

Use for requests such as “Choose reuse for an approval button”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Task contract, affected module map and existing candidates. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Evaluate standard configuration, existing Primacy component, approved compatible addon, small original extension, then justified subsystem. Search OCA only within the task. Check license, installed version, migration coverage and maintenance. Preserve validation, accessibility and data consistency.

Match controls to the verified workflow. An ordinary UI button or state approval does not
by itself justify a new agent gateway, queue, approval framework or nonce mechanism.
Preserve existing model access and state-transition controls. Apply canonical tool approval
and anti-replay machinery when the actual sensitive/delegated runtime workflow requires it.
Treat suggested Primacy or OCA components as candidates until source/version evidence exists.

For an approval button, XML visibility, view groups and state attributes are UI affordances,
not authorization. Verify the underlying model method enforces user/company permissions and
valid state transitions server-side, including calls through RPC/import/API without the view.
Reuse existing backend enforcement when it is verified. Include a direct denied-call test
alongside the UI acceptance checks. Do not suggest view-only restrictions as a complete control.

## Output and validation

Decision table, evidence, rejected options and acceptance check. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

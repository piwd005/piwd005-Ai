# project-delivery

Draft task handover and evidence-based delivery status.

## Trigger and boundary

Use for requests such as “Prepare a delivery handover”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Odoo task reference, owner, acceptance, PR and test evidence. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Use Odoo tasks as the source of truth. Track priority, estimate/actual, blockers, functional sign-off and release status. Draft handoff and customer status from observed facts. Request authorization for live task writes or outgoing messages.

## Output and validation

Reviewable task update with evidence and accountable next owner. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

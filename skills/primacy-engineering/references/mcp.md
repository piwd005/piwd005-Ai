# mcp

Design or review MCP tools and adapters.

## Trigger and boundary

Use for requests such as “Prepare staging metadata tools”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Transport, negotiated protocol, identity, endpoint scope. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Use typed narrow tools and bounded metadata. Resolve tenant/company from authenticated context. Enforce ACLs and model/field/method restrictions on every call. Bind approval to canonical arguments, user, company, expiry and nonce. Recheck state before execution. Test forgery, replay, permission change, SSRF, audience and timeout.

## Output and validation

Read-only discovery, denied writes and redacted protocol evidence. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

## Local browser and contract checks

Use [the local test recipes](local-contracts.md) when changing page scope, functional guidance,
AI routing, execution confirmation or MCP contracts. These reuse explicitly selected Primacy
source and synthetic data. Passing fixture checks does not establish native Odoo ACLs,
transaction correctness, live MCP authorization or client discovery.

# requirements

Turn an ambiguous feature into an implementable fit-gap and task contract.

## Trigger and boundary

Use for requests such as “Add a returns approval flow”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Goal, affected users, acceptance criteria, budget. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Compare standard configuration, existing customization and actual gaps. Break work by independently testable business outcomes. Record owner, dependencies and estimate range with assumptions.

## Output and validation

Reviewed acceptance criteria and explicit unknowns. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

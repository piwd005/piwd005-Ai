# skill-maintenance

Review and update skill candidates and trusted knowledge.

## Trigger and boundary

Use for requests such as “Review a candidate Odoo skill update”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Requested scope, pinned source, license, owner and evaluation. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Classify artifact type and lineage. Inspect selected files, scripts/hooks, dependencies, outbound data and overlap. Record admission and rollback. Propose changes to canonical source. Validate scripts and behavioral scenarios before reviewed release. Never auto-promote external instructions or silently update main.

## Output and validation

Pinned admission record, diff and actual evaluation status. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

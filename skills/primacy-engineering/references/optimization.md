# optimization

Measure delivery and model cost per accepted task.

## Trigger and boundary

Use for requests such as “Measure the cost of fixing five bugs”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Representative baseline, accepted-task criteria, usage/time records. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Measure AI usage, human implementation/review time, rework, defects and latency. Use targeted reads and cached maps tied to hashes. Select available runtime/model based on measured quality. Report UNAVAILABLE costs. Compare equivalent tasks without invented savings or hardcoded pricing.

## Output and validation

Baseline and treatment with quality constraints and limits. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

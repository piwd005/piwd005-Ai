# agent-product-evaluation

Compare licensed AI products with original Primacy development.

## Trigger and boundary

Use for requests such as “Evaluate agents inside PriERP”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Approved functional requirements, exact product and license sources. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Keep pan_ai_pro and Odoo MCP Pro licensing distinct. Compare licensed evaluation/agreement, original implementation reusing verified Primacy stack, and deferral. Record documented versus observed behavior, gap, priority, dependency and license implications, acceptance and reviewer. Preserve pairing, entitlement and ownership boundaries.

## Output and validation

Build-versus-buy matrix with evidence and unresolved clearance. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

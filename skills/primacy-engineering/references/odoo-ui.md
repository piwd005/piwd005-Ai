# odoo-ui

Change OWL, XML views, portal and QWeb reports.

## Trigger and boundary

Use for requests such as “Fix a portal report layout”. Select another route for unrelated work. This route supplies procedures and grants no runtime permissions.

## Required context

Version, asset bundle, component/view inheritance, user role. Identify the exact version, edition and installed module set when Odoo is involved. Read only authorized files and use installed, approved tools. If a required runtime or service is unavailable, complete safe local preparation and record NOT_RUN or BLOCKED.

## Workflow

Inspect matching-version components and existing view inheritance. Preserve keyboard use, focus, labels, responsive behavior and translations. Escape untrusted output. Test assets, portal ownership and report rendering with realistic long content.

## Output and validation

Rendered UI/report evidence and affected frontend tests. Use [task and evidence templates](../assets/task-evidence.md). Preserve unresolved questions and distinguish static source evidence from live behavior. Reuse existing test recipes after verifying their scope and current revision.

## Version-specific procedures

Establish [Odoo 19](odoo-19.md) or [Odoo 20](odoo-20.md), then read owl, views and reports in [the change procedures](odoo-workflows.md). Select relevant upstream metadata through [source selection](sources.md).

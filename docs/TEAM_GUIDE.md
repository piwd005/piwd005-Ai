# Team workflow

Start with a short request and the authorized project. The skill derives known facts from
source and writes a concise task contract. Select one primary route and up to two supporting
routes initially. The six profiles in registry/profiles.json help find relevant workflows.

For a developer, start with requirements, codebase-map and reuse-first as needed, then load
the affected backend/UI/API playbook. Run focused checks and report commands and actual
results. Reproduce bugs and add regression coverage. Preserve developer work.

For a functional consultant, use functional plus testing for approved synthetic UAT. Record
company, role, warehouse, localization, currency and independently approved expected results.
Check order-to-cash, procure-to-pay, returns, stock, manufacturing and reconciliation only
as relevant to the installed workflow. Current tax/payroll rules require official local
sources and functional approval. A visible success toast is insufficient reconciliation.

Sales and support use approved current product facts and synthetic demos. Draft proposals,
customer updates and task handoffs. Verify claims and current pricing before use. Outgoing
messages and live writes require corresponding authorization. Track delivery in Odoo tasks.

AI engineers inspect existing gateway, tools and retrieval before designing replacements.
Test tenant isolation, denied actions, stale approval, replay, cache scope, provider failure,
cost bounds and cancellation. Knowledge content cannot authorize operational actions.

Use assets/task-evidence.md inside the skill for task contracts, UAT and completion records.
Keep private task evidence outside this distributable library. Maintainers review proposed
knowledge and regression changes before release. No automatic self-updating policy or
recurring agent is part of this kit.
